# Open questions, assumptions and spec-vs-code differences

Status: draft

- **OQ-n:** open question, needs a decision by the owner.
- **SC-n:** observed difference between spec and code, documentation or project instructions. Candidate for a GitHub issue; the spec wins (P1).
- **A-n:** assumption made in the specs; to be confirmed.

Code references are to commit `1b38477` (branch base of `spec/kickoff-scaffold`).

## Assumptions

A-1 to A-5 were confirmed by the owner on 2026-10-07; they are binding like requirements.

| ID | Assumption | Spec ref |
|---|---|---|
| A-1 | _Confirmed._ Relative paths in the package config (`network_results_path`, `definitions_path`, `mapping_path`, `output_path`) are resolved against the current working directory. `pixi run` tasks run from the repository root, so the default `output_path` `resources` is the repository-root `resources/` directory. For a `pip install`ed package run elsewhere, `resources/` is relative to that working directory. | C1.8, configuration.md |
| A-2 | _Confirmed._ Two networks with the same investment year are an error (the output has one column/file per year). | C2.2 |
| A-3 | _Confirmed._ Owner decision "missing `energy_totals.csv` → only a warning; other variables can succeed" is specified as: one `WARNING` at initialisation, and every variable whose function declares `energy_totals` is skipped with its own `WARNING`. | C2.4 |
| A-4 | _Confirmed._ A result with zero rows is a structural error (C6.7): it carries no `location`/`unit` combination at all. "All values zero or NaN" (owner decision) is read as referring to results that have rows. | C6.7 |
| A-5 | _Confirmed._ For `intensive` variables, a group whose weights sum to 0 (e.g. a region without demand) gets the value NaN, not 0 and not an error; this is consistent with "NaN is a valid value" (C6.4). | C8.2 |
